# MoE 專家使用頻率分析

目標：在 16 GB 顯存 + 32 GB RAM 的機器上，跑放不進記憶體、必須從 SSD 讀取的 MoE 模型。
這一步先**量測**：用你自己的用途統計每個專家被選中的頻率，看冷熱分布有多不平均，再決定要不要做專家剪枝或冷熱分位元。

## 1. 準備校準文本
把你平常會問的問題、會處理的文章存成 `calib.txt`（純文字，建議 10～50 萬字）。
分布是依這份文本算的，越接近你的實際用途越準。

## 2. 收集專家選中次數（在你自己的電腦上）
```
llama-imatrix -m 模型-00001-of-0000N.gguf -f calib.txt -o imatrix.gguf -c 512 -ngl 99 --n-cpu-moe 999
```
- 輸出檔名一定要是 `.gguf`，才會包含每個專家的次數
- `--n-cpu-moe` 讓專家留在 CPU 端，其他部分放顯卡（參數依你平常跑的設定調整）
- 模型要從 SSD 讀，會跑得比較久；文本可以先用少一點試

## 3. 分析
```
pip install gguf numpy
python3 expert_usage.py --model 模型-00001-of-0000N.gguf --imatrix imatrix.gguf \
    --budget-gb 20 30 40 --ssd-gbps 3 --hot-out hot.json
```
- `--budget-gb`：可以拿來放專家的記憶體（顯存 + RAM 扣掉非專家權重、KV cache、系統用量）
- `--ssd-gbps`：SSD 實際讀取速度

## 輸出怎麼看
- **涵蓋 X% 路由需要多少比例的專家**：比例越小，代表越集中，剪枝和冷熱分層越有效
- **完全沒被選中的專家**：在你的用途下可以直接考慮剪掉的
- **命中率 / SSD 讀取量 / 上限 tok/s**：在各記憶體預算下，熱門專家放記憶體後，每個 token 還要從 SSD 讀多少

把整段輸出貼回來，就可以決定下一步：專家剪枝、冷熱分位元，或兩者一起做。
